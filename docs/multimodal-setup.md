# 条件式多模态辅助核对

## 当前完成情况

已实现支持图片输入的 Chat Completions 接口适配器、管理页面按钮、候选校验、
SQLite 调用记录和失败后的显式手动重试及每张图片最多三次请求的限制。49 项测试通过，其中外部返回由测试替身模拟。
**尚未使用真实密钥调用模型，也没有新的多模态准确率结论。**
YOLO/PaddleOCR 的识别配置不变，已保存的 OCR 和人工修正不会被模型建议覆盖。

## 配置

选择实际开通、支持 `image_url`（base64 图片）和 Chat Completions 的视觉模型。
只支持文字的模型不能用来核对原图；兼容接口不代表所有模型都支持图片。
接口格式参考 [阿里云官方图像理解文档](https://docs.modelstudio.console.alibabacloud.com/zh/model-studio/vision)。
从供应商控制台取得**完整接口地址、视觉模型名和密钥**，在本机填写，不要提交 GitHub。

在项目目录复制示例配置：

```bash
cp .env.example .env
```

编辑 `.env`：

- `RECEIPT_VISION_ENDPOINT`：完整 HTTPS 请求地址，包含 `/chat/completions`，不是网站首页或单独的 base URL。
- `RECEIPT_VISION_MODEL`：支持图片输入的模型 ID。
- `RECEIPT_VISION_API_KEY`：本机密钥；不放在聊天、截图或 GitHub。
- 三个价格变量可选。不填写时费用显示未知，不会把未知记成免费。

`.env` **不会被程序自动读取**。修改后，在同一个终端加载环境并启动：

```bash
set -a
source .env
set +a
.venv-paddle/bin/streamlit run streamlit_app.py --server.port 8512
```

`.env` 和 `.streamlit/secrets.toml` 已加入忽略列表。

## 使用

1. 上传 JPG/PNG 并运行原有识别流程。HEIC 仍需先转为 JPEG。
2. 仅在店名、日期、总金额被当前规则标记为需核对时，显示可用的“让 AI 辅助核对”按钮。
   未配置接口时按钮禁用；商品明细缺失不触发调用。
3. 点击按钮会向配置的服务发送 EXIF 校正、最长边 2400 像素的原图，以及最多三个
   相关字段裁剪图（最长边 1600 像素）。只提供指定字段的 OCR 候选，不另附商品 OCR 文本。
   **完整原图本身仍包含其可见内容**。
4. 模型仅返回指定字段的建议与依据。日期必须是有效的 YYYY-MM-DD；金额必须是完整整数日元。
   无效返回值不作为建议。格式有效仍不等于内容正确。
5. 你对照原图，将采用的建议手动填写到表单，点击保存。模型不会自动填写或改写你的值。
6. 历史票据也可请求辅助核对。其裁剪图若不在当前会话，发送完整原图；不为了补救重跑 OCR。

## 调用记录与重复费用

请求发送前，先以原图 SHA-256 在 `multimodal_attempts` 表中保留唯一记录；相同字节的图片，
无论刷新、重启、重新上传或打开历史票据，都不会自动再次发送。失败后可通过明确标注费用的按钮主动重试，总计最多三次。历史记录逐次保留。不同拍照角度/不同压缩文件有不同
摘要，属于不同图片，不做物理小票级去重。

记录模型、接口地址、指定字段、提示词版本、图片数量、结果/失败类型、响应 ID、耗时、
供应商返回的 token 数及费用估算。密钥、请求头和 base64 图片不写入调用记录；
原图仍由原有票据保存流程管理。记录位于 Git 忽略的本地票据数据库中。

- 无自动重试。HTTP 报错、超时、错误 JSON 或中断都保留记录，不影响人工保存。
- 未完成请求显示 `started`。如果进程被中断，它可能永久停留在此状态；当前版本不会自动补发，started 状态也不能重试，以免与进行中的请求冲突。
- 费用估算按配置的固定输入/输出单价乘以返回 token 数计算，可能与缓存、分档、图片计价或账单不一致。
  未配置单价/币种或缺少 token 数时显示未知。
- API 默认使用 90 秒超时（可通过 RECEIPT_VISION_TIMEOUT_SECONDS 配置 15–180 秒）、不跟随重定向、限制响应体大小；具体模型的请求参数兼容性仍需实测。
- 原始 `multimodal_plan.status=not_called` 是 OCR 时的规划快照。实际调用状态以独立调用记录为准。
